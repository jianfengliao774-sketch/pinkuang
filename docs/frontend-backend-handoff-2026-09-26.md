# 前端 v8 与后端数据交接（2026-09-26）

核对对象：朋友的 PR #9 最新头 `3c23ec67`（`web/` v8 演示）与本分支的合约、部署台、`PoolLens`。PR #9 明确声明钱包、项目、收益和投票均为演示；这些固定值不是链上数据源。本文件定义真实页面应读取的数据及目前不能声称已实现的能力，供前后端分别接入。

| 页面内容 | 真实来源与口径 |
| --- | --- |
| 项目目录、募集进度、矿机状态、已购金额、成员数 | 已验收 Factory 的 `poolCount/allPools` 与 `PoolLens.poolPage`；`PoolParams.circuitId` 是实际购入 NFT，替代采购后可不同于参考 NFT。分页、跨页固定同一区块；缺失 valid 位显示未知。 |
| 我的份额、锁定/可售份额、可领 BEM、池内待领 BNB | `PoolLens.positions`，尤其 `availableShares`，不能把 `balanceOf` 当作可售数。即使当前份额为零，旧持有人仍可能有收益、退款或售款。市场卖款另查 `ShareMarket.bnbOwed(account)`。 |
| 治理票数、门槛、期限、可投与可执行 | `PoolLens.governance`。不低于实际购机成本：赞成份额和快照地址数均严格过半；低于成本：至少 60/100 份，且赞成地址数严格过半。票数以快照为准，交易前重新模拟。 |
| 份额订单 | `ShareMarket.orders/orderExpiresAt` 是签名前权威状态；事件索引只负责发现、分页和历史。订单 7 天到期，表决冻结期间不能新挂单或成交，卖家仍可撤单。挂单份额仍由卖家持有并享有其收益。 |
| 收益中心 | `claimableBEM` 仅为已 `harvest()` 入池且已记账的可领余额；任何人可触发归集，成员本人逐池调用 `claim()` 领取，无 24 小时限制。页面三笔“批次”只是演示，合约没有按批次提款。历史池级 `Harvested` 和个人实际 `BemClaimed` 可索引，不能将池级事件推成个人每日应计收益。 |
| 公开流水、历史参与池、全局去重人数与订单列表 | 从已验收 Factory 部署块开始的链上事件索引；每项记录带区块、区块哈希、交易哈希和日志序号，并标明索引确认深度。当前余额、可交易状态仍须重新读链。 |
| 预计日产、NAND、来源市场、BEM 美元参考价 | 分别来自注明时间/区块的外部报价和矿机链上信息；没有可靠来源时显示未知。参考日产不是保证产出。页面短编号和价格浮点数只用于演示，不得用于交易编码。 |

真实身份用 `chainId + Factory + poolAddress` 标识池，用 `chainId + collection + tokenId` 标识矿机；所有 BNB/BEM 金额在接口中以十进制整数字符串传输，展示层才按精度格式化。任何索引或报价响应都要携带来源区块和时效；未知字段用 `null`，不可伪装成零。`web/lib/chain-client.mjs` 已提供同块 Lens 读取和未签名个人交易编码，但 PR #9 的最新页面还没有调用它，也没有主网已验收地址。部署台新增“导出前端合约清单”，只在已完成源码摘要及链上图核验的记录上开放；该清单仍需由前端按链反查，不能盲目信任导入文件。

## 数据落盘与浏览器边界

资产和权益的最终状态始终是 BSC 合约。历史列表由服务器的 [只读事件索引](../deploy/server/chain-index/README.md)写入 SQLite，HTTP 响应 `Cache-Control: no-store`；索引不完整时返回 503，不以浏览器缓存或演示数据补位。部署步骤、待确认份额市场交易和报价草稿由独立的[钱包认证操作日志](../deploy/server/JOURNAL.md)持久化到服务器 SQLite。浏览器只保留当前页面显示所需的内存状态和 HttpOnly 会话 cookie；一次性迁移旧 `localStorage` 交易记录，服务器确认后删除旧副本。旧钱包未连接或记录冲突时保留原始副本并暂停相关写操作，避免丢失待核对交易。

朋友负责的 `web/` v8 仍为静态演示，尚未接入上述服务器接口。正式页面必须以服务器索引发现历史，再按同一区块读取 Lens/Market 当前数值；断网或索引落后时显示未知或暂不可用。主题、语言等纯界面偏好可以由浏览器保存，资金池、订单、持仓、收益、交易哈希和报价计划不能以浏览器缓存作为持久记录或签名依据。

## 筹款与采购口径

已确认的规则是 `Firsto 参考日产能价 × 目标矿机预计日产能` 得出参考整机价，再加默认 10%（建池时可调）的额外募资；向上取整到 100 份的整数 wei。额外款不提高购机价格上限，未用款按购机时持份记账并由成员自行提取。最新 PR #9 的 `web/lib/economics.js` 用“外部挂牌价 × 1.01”算目标和每份金额，不能拿它覆盖此规则。

当前池合约仅能直买官网 `CircuitMarket` 有效挂单，买方付官网价 `P`，官网市场费从卖方所得扣。Firsto 页面所列官网订单若走 Firsto 路由，以及 Firsto 签名/批量订单，目前展示的买方总额可为 `P + 1%`，但现有池合约不能执行这些 Firsto 订单。Firsto 费用最终收款地址未独立证明；本项目官网代采服务费的费率和收款配置也尚未确定或实现。报价接口必须分别给出 `venue`、订单类型/ID、挂牌价、买方总价、来源区块、过期时间和 `executableByCurrentPool`；不能把 Firsto 的订单 ID 传给 `buyFromMarket()`，也不能把报价当成交承诺。详见[两渠道费用核对](procurement-fees-2026-09-26.md)。
