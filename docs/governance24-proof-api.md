# Governance 24-hour migration proof API

This release preserves the original governance and original immutable pool beacons as a 48-hour recovery route. It routes current business implementations, four existing UUPS endpoints, and Authority ownership through a new 24-hour timelock. It does not label the entire historical graph “24-hour”.

`deploy/shared/governance24-upgrade-plan.mjs` exports `GOVERNANCE24_UPGRADE_KIND`, `GOVERNANCE24_REVIEW_KIND`, `governance24UpgradeDeploymentOrder`, `governance24ArtifactNames`, `governance24Coverage(predecessorReview)`, `validateGovernance24UpgradeReview(input)`, `prepareGovernance24UpgradeDeployment(name, input, { deploymentsPrefix })`, and `buildGovernance24UpgradePlan(input)`.

The fixed dependency order has 13 CREATE receipts: FlexiblePurchase, PoolVault, BudgetPortfolioVault, PoolTimelock24, CoreGovernance24Beacon, PortfolioGovernance24Beacon, CoreGovernance24Dispatcher, PortfolioGovernance24Dispatcher, Governance24Validation, Governance24FreshPoolFactory, Governance24BudgetPortfolioFactory, CoreGovernance24ShareMarket, PortfolioGovernance24ShareMarket. Core and portfolio aliases use the corresponding common artifact, but remain separate deployments.

Input contains the complete `predecessorInput` accepted by the original Firsto batch reviewer, an independent `trustedPredecessorInputDigest`, the candidate `upgradeBundle` and independent `trustedUpgradeArtifactDigest`, `reviewCatalog` and independent `trustedReviewCatalogDigest`. Each artifact includes compiler-derived `immutableBindings` from AST ID to declaration name. The original Firsto batch candidate remains pending; historical proof is checked at the baseline before adding the new route. `governance24Coverage(predecessor, predecessorInput)` and `governance24LinkedAddressClosure(predecessor, predecessorInput)` follow every actual linked address recursively, including the historical Funds address reached by the old FirstoSale library. Historical addresses are resolved only from the independently trusted genesis artifacts. External NFT, token, mining and exchange contracts are explicitly outside platform governance.

The review catalog has schemaVersion 1, kind `platform-governance24-review-v1`, chainId 56, original profile, predecessorInputDigest, candidateArtifactDigest, canonical finalized anchor, exact predecessor bindings, exact generated coverage, preserved `pendingOperations`, and preservation `{corePools, portfolioPools, storage}`. Pending operations retain complete original single/batch parameters, computed ID and timestamp. Pool records pin the existing immutable address/codehash prefix. Each preflight enumerates all current pools, including legitimate later creations, and checks their original beacon and official factory. Preservation storage contains only immutable binding slots; mutable assets, rewards, shares, order books, and nonces are verified immediately before/after the atomic fork rehearsal instead of freezing live business across the waiting period.

`deploy/shared/governance24-upgrade-proof.mjs` exports `validateGovernance24UpgradePreflight(provider, input, options)`, `verifyGovernance24OperationReceipt(provider, {tx, receipt, expected, finalized})`, and `governance24VerifiedUpgrade(proof)`. Options follow the original preflight convention: phase prepared/unscheduled/scheduled/done; deployment receipt map; optional exact plan; original schedule and execute hashes; optional canonical finalized snapshot. `expected` for individual operation receipts additionally contains the complete pinned `input` and canonical `plan`; a calldata hash by itself cannot prove coverage.

Every retained original pending call is classified by `governance24PendingOperationEffects`. A direct original-beacon upgrade can undo the new dispatcher even after migration. Only canonical zero-value beacon upgrades covered by this complete business release become explicit unsigned cancellation prerequisites. `governance24Cancellations(input)` derives their stable `cancel-<operationId>` IDs before deployments are known. The plan contains complete `cancellations` with original arguments and timestamp kept as audit evidence. Unknown pending governance intents block plan preparation rather than being silently classified as covered.

After all 13 CREATE receipts, the user explicitly signs each displayed cancellation. The agent and proof never send it. `options.cancellationTxHashes` accepts either stable cancellation IDs or original operation IDs and must be the exact confirmed prefix. Each receipt is tied to the original reviewed proposer, canonical wallet envelope, exact `Cancelled` event, historical CANCELLER_ROLE and original pending timestamp immediately before, and zero timestamp after. Mere state-zero is insufficient. All covered conflicts must be cancelled before unscheduled/scheduled/done checks; nonconflicting operations retain their original timestamps. An `expected.operation` of `cancel` also requires `operationId` or stable `cancellationId`. Reverted signatures remain journal evidence and never authorize automatic nonce reuse.

The fixed seven-action original 48-hour batch upgrades two old beacons to dispatchers, upgrades four UUPS proxies and calls `migrateGovernance24(oldLock,newLock)` within each upgrade, then transfers Authority ownership. Each factory migration transfers its owner internally. All calls have zero ETH value, zero predecessor, and a unique nonzero salt. Both original batch envelopes, all seven events and six implementation events are checked; omission and extra actions fail closed. Only original user wallet signatures are used; the proof performs read RPCs exclusively and supports the existing pinned canonical MetaMask wrapper.

A done result contains actual current proof fields `codeUpgradeComplete`, `governanceMigrationComplete`, `coverageVerified`, `businessDelaySeconds` and `legacyRecoveryDelaySeconds`, and is branded in memory. Public JSON booleans and copies do not pass `governance24VerifiedUpgrade`. Every receipt requires exact CREATE nonce/sender/body, canonical inclusion, full constructor and linked runtime; the chain, snapshot, review anchor, and all transaction bodies are rechecked at completion.

The full original timelock event inventory from deployment through the independent current anchor is a required release-review input. Its completeness is established by the operator's read-only chain capture and independent release pin; the browser does not infer completeness from two remembered operations. Reorgs, changed current baseline, unknown pending intents, missing archive history, and source/artifact drift fail closed. Mutable assets, shares, orders, rewards and nonces are preserved by the reviewed migration source and immediate atomic fork before/after tests, not claimed from an across-delay equality check.
