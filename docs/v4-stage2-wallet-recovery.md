## 核验边界

- 仅支持固定官方 Manager、DeleGator、余额约束器运行时代码；只接受一笔零价值、零模式、精确目标与 calldata、自委托及指定余额约束的调用。批量、额外约束、其他目标和非规范编码均拒绝。
- 成功记录还必须绑定规范最终回执及唯一、精确的 Factory 权限变更事件。首次接纳需检查变更前后权限和当前完整接线进度；后端 PUT 独立核验，不采信浏览器自报成功。
- 已接纳历史的长期核验依据规范回执、精确执行证明与当前完整合约图；不会因钱包日后撤销委托或普通 RPC 不再提供旧状态而使已完成部署失效。尚未接纳的新交易缺历史状态时保持拒绝，不能用当前状态冒充历史证明。
- 失败重试保留原回执、费用和不可变尝试记录，核对最终性、nonce 和权限进度后才允许新的钱包交易。不会自动重发不明交易。
- 第二阶段 API 使用版本握手；旧页面收到 426 并要求刷新，不能因 Solidity 产物摘要相同而继续旧流程。

## 发布次序

1. 在同一干净提交构建独立 attestor 包和新部署台包，记录两个 manifest 的 SHA-256；Solidity artifact 摘要必须与已部署版本一致。
2. `make-attestor-plan.py` 从最新只读证据生成安装计划；`install-attestor.py --dry-run` 后才 `--apply`。该服务只能出具有限的地址持钥证明，使用独立用户、systemd credential、Unix socket 和无外网命名空间。公网页面进程只获得 IPC 凭证。
3. `update-completed-console.remote.py` 以单元文件、drop-in 和数据库记录摘要为前置条件切换部署台；保留第一阶段记录，保持第二阶段 HOLD 和代发关闭。并发改变时拒绝覆盖；回滚不恢复或重置数据库。
4. 完成链上状态、服务证明、访问控制和新版接口验收后，才能解除第二阶段 HOLD。用户仍需使用原部署钱包逐笔确认七笔交易。

验证地址持钥不等于开放代发。旧版与新版共用 Gas 地址时，新版交易代发仍需另行检查旧发送端停发和 nonce 协调；本次不开放自动购买或产品入口。attestor 默认只启动、不注册开机启动，重启后需明确启动并重新证明。

相关测试包括严格包装解码、前后权限、后端接纳、失败恢复、记录篡改、旧客户端拒绝、依赖打包闭包与部署脚本回滚。真实官方运行时代码的独立 Anvil 演练覆盖 16+7 步以及第三、七步的失败恢复；本地演练不代替用户主网最终回执验收。
