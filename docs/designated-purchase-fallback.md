# 指定购机：售价与日产能价双重 ±10% 替代

状态：候选代码，尚未部署或启用。正式站当前合约、部署制品摘要、已有项目的购买约定均未改变。本功能需要评审新的 Factory/Vault 实现、部署支持新签名格式的 Authority，再按现有治理时间锁核验、切换完整运行图。仅发布网页或打开环境开关不能启用旧合约。

## 购买约定

新建项目可明确选择“指定矿机 · ±10% 替代”。原矿机优先；原机已从建池时锁定的卖家地址转走，而且没有可执行的原机卖单时，才查替代矿机。地址变化也可能是赠送，因此界面不把它表述为“已确认售出”。取消挂单、超时、读取失败本身都不能触发替代。Keeper 先检查原机官网订单，再查询原机 Firsto V2 单笔签名订单。

替代机必须为相同官方 collection/系列、相同 taskId 的活跃、非最优、纯验证矿机；不能已由另一个拼矿项目占用。售价和售价除以当前链上预计日产出均需落在建池基准的 90%–110%，两个边界都包含在内。没有合格矿机时保留资金并等待；购机期限届满沿用原合约失败与退款路径，不扩大价格范围。

建池固定原卖家、collection/tokenId/taskId、验证权重、原卖单售价 P0、含费总支出 C0、预计日产 Y0、来源区块/时间/摘要。管理员签名覆盖这些字段，Vault 只允许在无份额的 Funding 状态由 Factory 配置一次。原有固定池和灵活池默认关闭本功能，不能升级后自动改成允许替代。

## 精确比较与预算

替代候选的卖单售价为 P1，当前预计日产为 Y1，两个条件同时成立：

```
9 * P0 <= 10 * P1 <= 11 * P0
9 * P0 * Y1 <= 10 * P1 * Y0 <= 11 * P0 * Y1
```

不比较五位小数的显示值，不用浮点，也不使用全市场或同类参考价代替原机基准。合约以完整 512 位乘积比较，避免先做除法造成边界误差。例如原机售价 1 BNB、日产 10 BEM，替代机售价 0.9 BNB、日产 13 BEM，其售价符合，但日产能价约为原来的 69.2%，不符合双边区间。

官网路径的售价已包含卖方承担的手续费；Firsto 路径的实际支出为卖价加订单的买方手续费（按协议整数取整）。售价带宽不再对总支出另加下限；含费总支出 C1 必须大于等于售价，且不超过以下三者的最小值：

```
priceCap = ceil(11 * C0 / 10)
已募集 totalRaised
Vault 扣除应付收益与待提 BNB 后的可用余额
```

为使固定 100 份的募集款足额覆盖上限，`targetRaise = ceil(priceCap / 100) * 100`。本模式固定预留 10%，不在该上限上重复加 10%。建池的原订单支出 C0 必须在 P0 与 2*P0 之间；批量 Firsto 订单不因本功能开放。

## 日产基准的来源

本功能使用官方 Mining 的 `currentRate()`、`UNVERIFIED_BPS()`、`totalVerifWeight()` 和矿机 `verifWeight`，定义为“官方链上当前预计日产”，不是 API 提供的裸估值。按官方页面的逐步整数计算：

```
unverifiedRate = floor(currentRate * UNVERIFIED_BPS / 10000)
verifiedRate   = currentRate - unverifiedRate
perSecond      = floor(verifiedRate * verifWeight / totalVerifWeight)
dailyAtomic    = perSecond * 86400
```

两次向下取整不得合并，不能用历史 P0/W0 冒充 P0/Y0。参数变化会改变当前日产；购买时重新计算 Y1，所以即使两台矿机的权重比例不变，也可能因全网参数变化失去资格。零产出、参数越界和溢出均拒绝。

前端把 NFT 核验、三项经济参数与版本读取固定在同一块并复核块哈希；参考时间最多 5 分钟。合约建池重新按当时链上参数算 Y0 并要求等于签名基准，变化则重新预览。购机付款前和 NFT/收益结清回调后都重验当前矿机条件、原机优先、双重区间、资金和唯一性；订单抢购或回调中变化应整笔回滚。

公式的离线来源：工作台缓存的官方 `Vr-frontend-abi.json` 和 `pod-main-DyW1b6Tm.js`。后者 SHA-256 为 `19c15433944aec63f4a03e0a483aa008b143ceca6a9302a6f01aa979356ee90e`，在字节偏移 654789 绑定官方 Mining，在 655835 读取同块参数，在 657411 使用上式。Firsto 缓存购买估算也采用该式；这不作为 Firsto 服务端全部报价在任意区块都完全一致的证明。本轮未调用正式付费报价 API 或链上交易。

## 接线与请求控制

- `createDesignatedPoolChecked` 是独立创建入口，使用独立的 `CreateDesignatedPool` EIP-712 类型；原 `CreatePool` 类型与域不变。
- 独立 ERC-7201 存储承载不可修改的政策；旧布局和旧资金出口不改。使用既有链接库，候选部署需重新核验其代码与链接，不能只替换主合约字节码。
- Relay 必须基于受信候选制品的精确 ABI 和同块 Factory/Vault/Authority 版本、运行图验证后接受新 selector；旧运行包在新增能力 RPC 前拒绝。Journal 的创建入口仅走 Authority；替代 Firsto 购买保持 keeper-only。
- 前端的新模式只在包含新 ABI、固定可信新部署清单的构建显示；选择前读取 Factory 版本，签名后的 Relay 再核验完整运行图。显示选项不单独触发付费图查询。认购预览读取一次 Vault 不可修改的条款，即使后续暂停创建也保留条款读取。旧运行图不增加该请求。
- 新模式锁定官网报价前核验 `listingFor/listingView` 一致性和 NFT 的市场授权。原机官网挂单可执行时，再补三项经济参数、一个 Factory 版本和一项块头读取，不请求 Firsto 详情或全市场产能参考价。需要 Firsto 时仅请求原机的准确订单。
- Keeper 要求显式 `--designated-fallback --venue auto`，先处理 pending 交易，再按原机、替代机顺序处理。替代查找复用有界候选缓存，逐项最终核验；不扫全市场、不增加新的高频循环。API 或核验失败不扩大购买权限。

## 信任边界

原价和含费支出是管理员签名锁定的报价。合约认证原机持有人、品质和链上日产，不能仅凭 digest 认证历史 Firsto 报价来源；摘要是承诺而非独立签名订单证明。前端核验可执行订单，Relay 对当前可执行官网原单核对其售价和卖家；无官网原单时不得声称服务端或合约认证了 Firsto JSON。

合约强制原机官网可执行挂单优先。Firsto 原机优先由 Keeper 的准确编号查询与签名订单验证执行；公开 API 暴露 bestAsk，不是完整订单簿，无法保证发现未返回的其他签名订单。只有被发现且通过链上核验的原订单可优先执行；不把 API 没返回订单表述为全市场不存在原机订单。

## 核验与上线边界

候选测试覆盖两个区间的边界、原机优先、转手但无效订单、费用与余额、同任务/纯验证要求、矿机登记、回调中的状态变化、旧池禁用、独立签名与篡改字段、规范 calldata 和低成本读取。正式制品构建使用已锁定的 Solidity 0.8.24、optimizer runs=1、viaIR=false，并严格执行 24,576 字节部署上限；测试 VM 能部署不能替代此检查。

本分支保留旧的发布制品和链上地址，仅生成独立候选制品以供审核。上线必须在合约、Authority、网站、relay 和 keeper 的同一受信运行图完成核验后进行；任何测试通过或代码合并都不代表正式站已启用。
