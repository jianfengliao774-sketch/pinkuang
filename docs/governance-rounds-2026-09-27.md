# 整机出售提案轮次交接（2026-09-27）

`PoolVault.activeProposalId()` 是当前七天**轮次的首个提案 ID**，不代表该轮只有一个售价。首个提案建立当前持份和地址数快照，并冻结份额变更 24 小时；这段时间内其他持有人可各发起自己的候选提案，所有候选共用首提案的 `snapshotTs`、`snapshotMemberCount` 和 `endsAt`。同一地址仍须间隔七天才能再次提案，轮次之间也至少间隔七天；未执行的轮次结束后，剩余六天允许份额交易。

在同一个链上区块读取 `activeProposalId()` 和 `nextProposalId()`。当前轮候选 ID 位于 `[activeProposalId, nextProposalId)`；逐个读取 `getProposal(id)`，只展示与首提案快照、成员数和截止时间一致的候选。`PoolLens.governance(pool, account)` **只返回首提案**的派生状态，不是候选清单；页面/服务器索引必须展示所有候选的价格、提案人、赞成票、阈值、截止时间和该钱包是否已投。也可从 `SaleProposed` 与 `SaleSnapshotRecorded` 事件发现候选，但签名和显示当前状态前要同块重读合约。历史旧格式提案不能投票或执行，不能因事件存在就显示可执行。

每个候选分别投票。售价不低于实际购机价需要超过 50 份且快照地址数过半；低于实际购机价仍需至少 60 份且快照地址数过半。多个候选可能同时达标，**首个成功调用 `executeSale(candidateId)` 的候选成为挂牌价格**，资金池随即进入 `Listed`，其余候选不能再执行。前端须让投票人看清自己支持的具体售价，执行前重新读取候选与池状态并模拟；`listedProposalId()` 可以是轮内任何候选 ID。

修复不增加存储字段或改变外部函数签名；部署产物仍须按修改后的源码重新生成并核对。少数持有人仍可先开启轮次并冻结 24 小时，但不能独占该轮的售价入口。若多数人未在窗口内提出并通过候选，七天轮次间隔仍会延后下次出售。
