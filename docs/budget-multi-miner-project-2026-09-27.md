# 固定 BNB 预算、一个项目购买多台矿机

2026-09-27 用户已确认：先确定一个 BNB 募集目标，达标后在预算内尽量购买多台合格矿机；这些矿机共同归属一个项目的 100 份，收益按份额分配。之前的单机项目与部署继续按原规则运行。

## 当前实现状态

`deploy/scripts/budget-acquisition.mjs` 是**只读选机规划器**，不创建项目、不动用钱包、不发购机交易。输入必须是同一区块、覆盖完整且不超过五分钟的已核验候选；若传入 Firsto 候选，还必须单独提供同区块、完整、未过期的 Firsto 全量扫描证明，官网扫描结果不能替它背书。它按官网市场价格升序先选，再选可执行的 Firsto 签名挂单；相同 NFT 只入选一次，单台成本不得超过由**独立输入的整台绝对上限和单位权重上限重新计算**的价格上限，不能信任候选对象自报的上限。Firsto 买方手续费已经包含在其成本中。官网采购服务费按已购官网矿机价格的 1% 从未使用预算里扣，剩余可退金额按 100 份分配；可退余额不足时，不为了收费而挤占购机款。计算全程使用整数 Wei。

`deploy/scripts/budget-official-discovery.mjs` 补齐官网市场的只读候选发现：读取官方快照，枚举快照后新挂单，在同一个 BSC 区块重查两种官方矿机的挂单、`listingFor`、NFT 持有人及 Mining 状态，并在结束时重验区块哈希。有效纯验证矿机按真实链上挂单价排序；漏单过多、来源滞后、RPC 错误或重组均失败，不把部分扫描结果称为“最低价”。它要求建池时已审阅的单台绝对价格上限与每单位验证权重上限；上限不是募集总额。

Firsto 全量候选扫描及每笔签名订单的同区块可执行性校验尚未接到多机规划器，因而现阶段只有官网发现结果可作为完整的官方市场输入。不能把 Firsto 的一页低价列表当作全量最低价覆盖，也不能用网页估算触发采购。

**旧单机合约不能执行这份计划。** `PoolVault` 在第一台 NFT 购入后进入 `Active` 并结算全部余额；NFT 回调、矿币领取、出售与 Factory 的唯一性登记均绑定单台 `circuits/circuitId`。当前 `forge build --sizes` 显示 `PoolFactory` 运行时代码 24,534 字节，距 24,576 上限仅 42 字节；`PoolVault` 24,512 字节，仅余 64 字节。不能在旧合约追加几个入口后直接升级。

本分支新增的 `BudgetPortfolioFactory.sol`、`BudgetPortfolioVault.sol` 和 `TransferableBemRewards.sol` 是**独立可升级共同权益项目的待审实现**：项目发行唯一的 100 份共同权益，逐台认购由既有 Factory 创建的单机 PoolVault 的全部 100 份。每台 NFT 仍由其子池购买、登记、持有和严格结清；包装项目是各子池的唯一份额持有人，归集其 BEM 和 BNB，再向包装项目成员分账。子池只在实际选定候选时由原 Factory 的 operator 创建，避免预先占用大量矿机编号。包装项目只接受同一已验收 Factory 的 `isPool`、`pool.params`、`state` 和唯一性登记均匹配的全新子池；每个子池只认购一次，单台价格上限、总预算与来源费用逐笔复核。该结构复用原 Factory 的矿机唯一性，旧子池合约无需装下多台 NFT。

包装项目必须用受 48 小时延迟治理的 Beacon/代理升级；不得把底层子池份额转给 operator。包装项目持有子池份额期间，真实成员的出售授权须先在包装项目链上投票，通过后才能由包装项目向子池提案、投票并执行；不能让包装项目在子池作为单一地址时绕过真实成员门槛。份额市场需要为包装项目 token 接入已验收的双边 1% 费用规则，不能把底层子池份额直接挂牌给个人。

`contracts/test/unit/BudgetWrapperCompatibility.t.sol` 已以现有子池和采购市场 mock 验证两个关键组合条件：一个合约地址可分别以 100 份认购、采购两个子池，拿回各自余款并归集 BEM；第二台采购失败会原子回滚其认购、付款和 NFT 状态，不影响已成功的第一台。这是**兼容性测试合约**，不是项目合约，不能部署为正式产品。它没有证明真实市场、Firsto、治理和二级份额市场的端到端安全。

`contracts/test/unit/BudgetPortfolio.t.sol` 进一步覆盖新项目在 mock 市场的两台原子采购、零台退款、部分失败、双钱包争最后一份、BEM 随份额转让、手动领取后不重复转移、一次合并领取、份额市场买卖双方各 1% 费用、低价出售的地址和 60 份双门槛，以及出售款归属。`contracts/test/unit/TransferableBemRewards.t.sol` 包含 256 轮随机收款/领取/转让的 BEM 守恒测试。源码绑定的 ABI/字节码已加入 `deploy/public/deployment-artifacts.json`，初始升级安全校验已通过。新合约尚未做 Firsto 真实签名订单、BSC fork、新旧版本升级存储布局对比、生产部署脚本及清单、后端索引和前端交易接线验收。

首次远端合约检查在 [run 36332949129](https://github.com/jianfengliao774-sketch/pinkuang/actions/runs/36332949129) 的 Slither `--fail-medium` 阶段失败；编译、442 项单元及不变量测试、升级检查已通过。后续修复把过期出售提案在调用子池前清除，用减法表达整数余数守恒，且仅对持有 `nonReentrant` 锁的跨合约调用、实际 BEM 余额差校验和精确零收款校验附逐行 detector 说明。本机相同 Slither 0.11.5 和 `--fail-medium` 已退出 0；仍需看重新触发的远端 CI 结果，不能将首次失败说成通过。

## 上链规则

1. 募集目标在建池时固定并可被 100 整除；任一钱包可购买 1–100 份。达标后立刻开放逐台采购，募集预算、单台已付价格、矿机列表及未花余额均为链上状态。
2. 选机服务从官网完整市场快照开始，核对同一区块的有效订单、当前 NFT 持有人、挖矿中、非最优、纯验证权重及跨项目唯一性；官网候选无法覆盖预算时才考虑 Firsto 可执行的签名订单。列表排序是**所核验市场快照中的最低价**，不是对交易执行时全市场最低价的链上证明。页面须显示快照区块与时间。
3. 运营 keeper 对每台矿机单独发交易：重新核对订单、价格、卖家、矿机身份与质量、单台参考价格上限、总预算余额、来源手续费及唯一性，再付款和验收 NFT。挂单消失或涨价时跳过该候选，重新规划；任何失败交易原子回滚，不消耗募集余额。采购入口只给链上 operator/keeper，防止卖家自行把高价矿机塞进项目。
4. 每笔交易只处理一台矿机；矿机清单、收益归集、索引和前端按页处理。`n` 不设置业务上的固定台数，但不得让一笔交易随矿机数增长而变得不可执行。
5. 购机期限结束后，若至少买到一台则项目进入运行状态，未用预算扣除经确认的官网采购服务费后，按募集时的份额归属退回。若一台也未购成，则全额退回。任何人可完成结算；结算不能在期限内被运营方提前终止以逃避继续采购。
6. 每台矿机单独发起挖矿收益领取，BEM 先进入项目合约，再统一按共享 100 份记账；持有人本人随时领取。用户最新明确：**尚未由个人手动领取的矿机 BEM 收益随份额一起转给买家**；已领部分不会再次转移。一个钱包持有不同来源份额时，转出的未领权益按该钱包的份额比例拆分并确定整数余数归属；份额成交前不用逐台 harvest，避免矿机数导致交易耗尽 Gas。整机出售须指定具体矿机并经链上投票，价格低于该台实际购价时至少 60 份赞成，同时满足现行参与地址门槛。运营钱包在发布该台矿机的 Firsto 挂单前支付 Gas 归集 BEM，并将实际到账的 BEM 记入项目共同权益；无需在未来成交瞬间再次要求待领余额归零。单台出售收 1% 平台费，无销毁。出售所得按出售时份额单独记账，不随之后的份额转让转移；全部矿机售完项目关闭。

2026-09-28 出售渠道及收益边界已由用户更新：**仅在 Firsto 原生挂单；后台钱包在挂单前实际归集 BEM，挂单后新增矿机收益随 NFT 给买家；成交时不做严格零待领结清**。上段是目标行为，当前开发代码仍走内部直接出售且严格结清，不代表新渠道已实现。合约与页面改动、外部发布服务兼容性及验收要求见 [Firsto 整机出售决议](firsto-exclusive-sale-2026-09-28.md)。
7. 份额转让和市场成交在采购未结算及出售表决期间冻结。现有份额市场对新项目的支持必须依据新合约的真实权限、锁仓、转移和 BEM 未领权益随份额转移的记账接口重新验收。购机余款固定归购机结算时的份额持有人，后续卖出份额不改变这笔退款的收款人。

## 接口及发布边界

- 新的包装项目 Factory/Beacon 必须沿用 48 小时升级延迟、单钱包治理路径；底层矿机只由现有 Factory 创建的子池持有和登记。若改为新 Factory 直接持有 NFT，就必须先解决跨 Factory 的永久矿机唯一性，不能上线彼此互不知晓的登记。
- 后端保存按 `chainId + Factory + project` 定位的项目、候选快照、报价版本、交易意图、回执与索引状态；浏览器缓存不是资金或订单真源。钱包只确认精确的单笔交易，不把离线排序结果当链上授权。
- 新合约的源码、产物、ABI、部署清单和运行时代码摘要必须一致。主网升级与采购由用户钱包按既有治理步骤签署；只读规划器的通过测试不能视为主网多机功能已部署。
- 本 PR 现在包含上述**待审新合约源码和源码绑定部署产物**，但没有主网部署或前端交易入口。按用户此前要求，合约变更单列在上面的三个新文件，旧 Factory/Vault 源码未改。Firsto 全量发现、真实 BSC fork、新旧版本升级验证、生产部署脚本/清单、服务端索引、前端接线和独立审计均未完成；不得把这个草稿分支发布成可募集资金的多机项目。

## 必须通过的验收

- 两个钱包同时买最后一份、同一钱包买满 100 份；并发 keeper 购买同一 NFT、不同市场同一 NFT、旧项目和新项目抢同一 NFT。
- 报价从最低变高、卖家撤单、矿机停挖、任务或权重变化、Firsto 签名/费率/nonce 变化、官方市场优先顺序、单台价格与总预算上限。
- 零台、部分、全部采购成功；逐台领取失败但其他矿机仍可收矿币；项目余款、服务费、售出款和矿币守恒。
- 收益先到项目后分别发生手动领取、全部份额转让、部分份额转让、混合来源份额、零碎整数余数；未领 BEM 随转让移动，已领 BEM 不重复给买家；出售投票快照、低于该台成本的 60 份门槛、挂单前归集失败不发布、挂单后新增矿机收益归 NFT 买家、售完最后一台关闭项目。
