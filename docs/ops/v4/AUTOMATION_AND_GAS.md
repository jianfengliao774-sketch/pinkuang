# 自动化范围与 Gas 支付

本文记录本版实际提供的调用方式。用户于 2026-09-30 明确：领取、退款、撤单由用户自己支付 Gas，平台 Gas 钱包主要用于必要的后台自动调用。规则来源见 [Gas 决策记录](../../decisions/2026-09-30-gas-payment.md)。

## 执行方式

| 操作 | 触发方式 | Gas 支付者 |
|---|---|---|
| 创建单机或预算项目 | 当前管理员确认明确参数，签名后由 Authority 执行 | 平台 |
| 单机满募采购 | 后台扫描已募足、未超期的项目，优先官方市场；官方订单不能完整核查时不转 Firsto | 平台；购机本金由矿池合约支付 |
| 单机 Firsto 采购 | 后台仅采购项目原定 NFT 的受支持 V2 签名订单，不自动更换目标或执行 batch | 平台 |
| 多机预算采购 | 管理员逐台确认；每台先签建子池，再签指定订单和最高支出的购买，页面保留可恢复队列 | 平台；本金由预算父池支付 |
| 已购单机和预算子池启动挖矿 | 后台扫描已注册 Active 子池，验证状态、冷却和工作证明后 arm/start | 平台 |
| 停挖/reclaim | 管理员确认精确矿池与矿机 key 后签名 | 平台 |
| BEM 收集、父池归集及领取 | 用户触发 harvest / collectChildBem / claim / claimBem | 调用者 |
| 退款建账、结束预算采购、提取余款 | 按合约条件触发 finalizeFailure / finalizeFundingFailure / finalizeAcquisition 等，再领取款项 | 调用者 |
| 份额挂单、买卖、撤单 | 用户直接发起 | 用户 |
| 整机出售提案、投票、执行与成交 | 用户直接发起；必要的价格参考和审核由管理员另行签名 | 用户；管理员后台调用由平台支付 |
| 预算子池售款结算到父池 | 用户触发 settleChildSale，再领取父池款项 | 调用者 |
| 平台手续费领取 | 管理员明确签名 claimFees，收款者须符合已部署合约规则 | 平台；与会员领取收益不同 |

每台预算采购的“两次确认”指两笔独立操作，并不要求两位不同管理员共同签名。现有常驻采购服务只枚举单机 Factory，不会在预算满募后自行创建全部子池或签署管理员授权。矿机启动服务会扫描同一 Factory 登记的预算子池。

不存在每天自动归集或自动把退款转进每个钱包的任务。单机份额转移和整机成交中的严格收益结清是同笔合约逻辑；它不能替代预算父池的收益归集或售款结算操作。Firsto 出售仍在本站按受控流程成交，尚未开放其原生页面的任意外部直购。

## 服务与交易边界

- `pinkuang-v4-purchase.service`：单机采购，对应 `deploy/scripts/purchase-supervisor.mjs`、`purchase-keeper.mjs`。
- `pinkuang-v4-mining.service`：已购矿机监测与启动，对应 `deploy/scripts/mining-supervisor.mjs`、`mining-keeper.mjs`。
- `pinkuang-v4-signer.service`：校验管理员签名并执行受限后台调用，对应 `deploy/server/authority-signer.mjs`、`authority-relay-api.mjs`。
- 普通成员交易直接使用成员钱包；`deploy/shared/fresh-user-exits.mjs` 同时约束浏览器和后台的既有退出操作，不将这些操作交给平台代付。

后台交易的原生币 `value` 为零，Gas 钱包只付手续费。出现未知交易、非规范回执、证明失败或费用超限时，后台停止该操作并保留账本。不得删除锁或交易记录来跳过核对。手动 Authority 恢复须排除旧版采购以及新版 signer、采购、挖矿全部发送者，见 [恢复流程](../../../deploy/ops/v4/AUTHORITY_RELAY_RECOVERY.md)。

运行计划的费用上限分别按账本累计：Authority 单账本 0.01 BNB、采购每池账本 0.01 BNB、挖矿每池账本 0.02 BNB，Gas 单价上限均为 1 Gwei。它们不是一个全平台共享总额度；部署预算也不是长期运营预算。实际启用值以发布验收保存的服务配置为准。

## 验收边界

源码回归、浏览器模拟、链上部署回执和空项目扫描分别证明不同事项。新站真实采购、BEM 领取或退款需要真实项目和用户钱包操作后，才能根据回执、NFT 所有权和实际资金变化确认成功。不可把机器状态显示就绪或旧站成交记录当作新合约业务成交证明。
