# Formal operator fee collection

It discovers fee sources from the active formal core and budget Factory registries, including closed pools and registered budget children. It only includes sources whose treasury is the current PlatformAuthority and whose exact BNB credit for that Authority is positive. The displayed total also includes BNB and BEM already held by the Authority. Mining BEM fees arrive at the Authority during harvest; member rewards are never claimed by this pane.

All reads use one canonical BSC block and the formal manifest's bindings and code hashes. The existing same-origin read proxy handles contract views. Since that proxy does not allow `eth_getBalance`, the connected wallet supplies only the Authority's balance and proof of the same chain/block; no RPC allowlist or backend is changed. The pane retains its last balance while refreshing every 30 seconds when visible. A click reads a new complete plan before requesting signatures. All amounts display five decimal places; calculations and signed arguments retain exact integers.

Collection uses the existing `claimFees` EIP-712 action. Its recipient is the current administrator, as required by PlatformAuthority; the existing Gas wallet relays it. Each transaction has at most 24 source addresses. Additional batches proceed automatically after the preceding hash is confirmed, with five-second status polling and at least 15 seconds between batch starts to respect relay limits. Each batch needs its own administrator signature. Zero balance causes no transaction. Cancellation, unknown submission/receipt, read failure, permission changes or a changed wallet/deployment stop subsequent batches. Confirmed receipt links and the stopping reason stay visible. Reload recovery relies on the relay journal and a new balance scan, rather than resending an unresolved command.

Regression coverage exercises complete 501-pool enumeration, child and historical sources, deduplication, direct-only and zero balances, cross-provider block binding, concurrency/abort, exact large integers, batch limits/order/throttling, wallet cancellation, unknown results, and React lifecycle changes caused by parent busy state or equivalent config objects. ## Withdrawal history

The Fees pane also shows finalized `PlatformAuthority.FeesClaimed` events for this formal deployment: receiving administrator, time, separate BNB/BEM amounts with five decimal places, and the transaction receipt. The event's administrator is the recipient; the Gas transaction sender is not presented as the claimant. Records from former administrators remain visible. There are no manual addresses or filters.

The server's configured read RPC supplies event lookup, restricted to the current formal Authority and the exact `FeesClaimed` topic in fixed ranges of at most 5,000 blocks. General log scans and signing/sending RPCs remain unavailable. The read provider verifies the Authority's own creation receipt to determine the history start; the later Factory/genesis deployment block is not a log-query lower bound. It also verifies event receipts and canonical finalized blocks. Pages contain at most 20 records, use bounded ranges and retain continuation through empty ranges. Reads have a 30-second cache and four-request concurrency limit. Only the visible newest page refreshes every 30 seconds; confirmed collection refreshes it immediately. Failed or cancelled reads do not become an empty history or affect the collection controls. Fee balance/history reads do not depend on purchase or mining worker readiness.
