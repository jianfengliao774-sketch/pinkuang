# Firsto 单笔签名采购：操作与交付边界

更新：2026-09-27。本说明对应开发分支中的新采购能力，**不表示现有主网合约已经升级，也不表示自动采购服务已经启用**。现有网站、既有部署记录与合约基线见 [主网页面接入记录](mainnet-product-integration.md)。自动执行器的钱包密钥、独占运行方式和实际 Gas 预算尚未配置；本轮没有发送主网交易。

## 支持范围

`PoolVault.buyFromFirsto(uint8 kind, bytes encodedOrder)` 仅接受 `kind=0` 的 Firsto Signed Ask V2。订单编码为官方 `SignedAsk` 元组和卖家签名，不接受任意目标合约、任意调用数据或外部指定 NFT 接收人；接收人固定为资金池。`kind=1` 批量订单拒绝执行，其公开声明与实测运行时代码的来源差异尚未解决。

Firsto 合约固定为 `0x33423244F9a5bF81b12B1a018aF6F4e079B97f29`，网络固定为 BSC `56`。JS 预检同时校验代理代码、EIP-1967 实现及实现代码摘要；全部状态取自同一指定区块，结束时复查链号、区块号、哈希与时间。并发读取全部结束后才报告成功或失败。卖家签名支持 EIP-712 及 ERC-1271；订单撤销、持有人、出售授权、到期时间、暂停状态、协议版本和手续费 epoch 均需重新核对。

本路径只购买池创建时的原始 `collection + tokenId`，固定方案和灵活方案都不能用 Firsto 订单替换成另一台矿机。池还须处于 Funded 且未过购机截止时间。完整交易模拟与链上执行检查资金、NFT 身份、活跃/纯验证/非最优条件、灵活方案的任务及权重限价、旧持有人收益结清、预期 NFT 回调和成交后状态。模拟成功不保证抢先成交。

实际支出为 `price + floor(price × feeBps / 10000)`，购机上限约束的是这笔**含 Firsto 费用的总额**。官网 CircuitMarket 成交价仍按官网规则处理，不能拿 Firsto 买方总额替代。此实现没有另加本项目采购佣金，也不构成采购服务费分流方案已经上线的证明。

## Keeper 使用

在支持 Node.js 24 的 Linux 环境、仓库 `deploy/` 目录执行。以下均为占位地址与路径，不可照抄发送：

```sh
node scripts/purchase-keeper.mjs \
  --factory 0xFACTORY --pool 0xPOOL \
  --venue auto --journal /private/path/pool.json --once
```

不带 `--send` 时只读取和模拟，不使用私钥、不签名、不广播。Firsto 一次性检查会等待有界订单发现；持续运行可在筹款期间预热。按原目标编号及 TapeOut/Behemoth 系列搜索，默认最多 3 页，每页 50 行，总响应上限 2 MiB，总发现时限 20 秒；不接受重定向或非 JSON。搜索不到不表示整个平台没有订单。发现后只保留规范签名单，发送前重新获取池边界并再次验证订单，最后执行完整 Pool `estimateGas`。

`--venue` 默认仍是 `official`，避免旧部署意外进入未启用的 Firsto 路径。显式 `--venue auto` 时先尝试官网原目标，再读取官网独立挂单快照，逐笔复查该系列所有有效挂单的链上现价，并补查快照之后新增的挂单；随后逐台核对同任务、验证权重及单位产能限价，并对每笔候选执行最新挂单读取与完整 Pool 模拟。Firsto 原目标签名单准备好后、真正发送前会**强制重新完整扫描官网**，避免旧挂单在 Firsto 查询期间降价而被遗漏。只有官网扫描完成、快照生成时间不超过 6 分钟、挂单编号边界未改变且没有读取或模拟失败时，才尝试 Firsto。官网快照不可用、过旧、超出扫描上限或验证不确定时暂停 Firsto 回退；不会把读取错误当成官网无货。快照仍不是所有历史挂单状态的数学证明，交易打包前也可能发生抢先成交或改价。

`firsto-signed` 保留显式单渠道只读诊断与旧 journal 恢复用途；CLI 和导出的运行入口都禁止用它发送新采购，避免跳过官网候选。Firsto 原目标约束属于这条 keeper 采购路线；链上另阻止原目标矿机在官网有合格挂单时绕路 Firsto，但无法在链上穷举**其他**官网候选。因此生产自动采购应使用 `auto`，并由单一 keeper 钱包和 journal 协调。扫描完成至交易打包期间，旧官网替代挂单仍可改变；官网挂单也能在合约允许的价格上限内提价。当前主网 Vault 未升级为本开发分支，不能把网页显示的 Firsto 订单当成已可购买；正式发送前仍需部署版本与 ABI 验收。

实际启用需确认执行钱包与 Gas 总预算。systemd 服务优先用 `LoadCredential=keeper-private-key:/etc/pinkuang/keeper-private-key`，程序从 `$CREDENTIALS_DIRECTORY/keeper-private-key` 读取；兼容旧的 `KEEPER_PRIVATE_KEY` 环境变量，但两者同时存在时拒绝发送。凭据源文件由 root 保管，不要把私钥放入命令参数、源码、服务 `Environment=`、日志或聊天。`--send` 要求显式 journal 路径；`--max-gas-bnb` 和 `--max-gas-price-gwei` 限制累计 Gas 支出及单价，程序默认值不是用户已授权的费用预算。采购资金来自已募集的池，keeper 交易附带 BNB 固定为零。完整的服务配置及上线检查见 [keeper 凭据与入口安全复核](security-low-risk-review-2026-09-28.md)。

本机钱包锁和池锁不能协调另一台服务器、浏览器钱包或后台 journal。执行钱包运行期间不得被其它执行器或人工交易并用；产品后台仅允许运营地址发起采购，独立 keeper 仍服从合约本身的调用权限。当前没有配置或启动自动采购服务。

## 待确认与恢复

原始签名交易、确定哈希和 nonce 先以 0600 文件持久保存，目录锁采用 0700；Linux 上验证这些要求。Windows 不满足现有目录 fsync/权限前提时不能将失败解释为可安全发送。

未确认 journal 始终优先处理，不能换订单、换 nonce 或删除历史来继续。普通循环不重播、不自动提价。恢复需显式 `--send --once`，三选一：`--rebroadcast` 重播完全相同字节；`--speed-up` 保持同 nonce、同池、同订单，仅在预算内提高费用；`--cancel-pending` 以同 nonce 空数据、零值自转账尝试取消。

Firsto 重播和加速从 **journal 原始 calldata** 识别采购路径，不能通过修改 `venue` 标签或换 CLI 模式跳过保护。每次重播或签署加速交易前，按最新区块重新验证原订单及固定运行时代码。实现变化、手续费变化、订单过期或签名失效时停止发送，保留旧记录。已经发出的旧签名仍可能成交；停止程序或下调预算不能撤销它。

只读收据恢复、显式取消及原样重播已签取消交易不依赖 Firsto 仍可成交，避免已失效订单把 nonce 永久锁住。结案仍要求精确交易身份、canonical 区块、至少两次确认及 BSC `finalized` 证明。旧官网记录保留原恢复规则；费用账本、原哈希及取消历史不能被覆盖。更详细的既有保护见 [采购与恢复说明](purchase-execution.md)，其中旧版“仅支持官网”表述应结合本开发分支说明阅读。

## 矿机唯一项目与升级

当前实现按“每台矿机只能创建一个项目”采用**永久唯一**：同一 Factory 内以 `collection + tokenId` 为键，退款、到期、关闭或整机出售后均不释放。灵活采购的参考矿机和实际购入矿机均需避免与其他池重复占用；不同 Factory 不共享此映射。

这是新增合约能力，网页发布不会自动改变主网行为。既有 Factory 与 Beacon 升级、机器登记初始化/历史回填、编译产物与 ABI 导出、可信部署记录和运行时代码验收必须作为实际升级工作处理，并由用户钱包按治理流程授权。迁移分批最多 64 池，登记未就绪前新建/采购失败关闭；历史重复冲突不能静默覆盖。应在签署具体升级提案前明确旧池适用范围与迁移结果。当前没有激活这次链上升级。

Firsto 使用可升级第三方合约。签名前代码摘要检查不能阻止其在交易打包前升级，也不能代替第三方完整源代码审计。主网真实采购验收仍须逐项核对授权的合约版本、含费支出、NFT 到池、收益归属与退款账本；不得把 mock 通过写成主网全流程通过。
