# 采购保护与交易恢复

当前实现只执行官网 CircuitMarket 采购。Firsto 用于发现候选和参考报价，Firsto 签名/批量订单及拼矿自收采购服务费尚未接入。以下保护已经落入开发分支，尚未部署主网。

## 什么矿机允许买

建池时，合约从参考 NFT 的官方 Mining 数据读取并锁定 taskId。原目标由官方 collection + tokenId 唯一确定，不能用名称或网页图片代替身份。替代矿机必须同 collection、同 taskId、活跃、纯验证、非最优、达到固定的最低验证权重，且成交价不超过 priceCap。taskId 相同并不保证门数、成本和未来日产收益完全相同。

原目标仍有价格在 cap 内且符合质量条件的官网挂单时，任何调用者都不能跳过它买替代品。价格上限是最大授权支出，不是保证全市场最低价；卖方仍可能在上限内调整价格。链上读取失败不会被解释成原目标无货。原挂单静态有效，但卖家拒收款或旧收益结清失败时，替代也会被拒绝；需等挂单真实失效、故障恢复或采购到期。

每次成交在同一笔交易内检查挂单身份、价格、矿机资格、预期 NFT 回调、NFT 到池及成交后的矿机资格。不符合就整笔回滚，成交款不会留给卖家；已经消耗的 Gas 不会退回。池只有在 Funded 且未过采购截止时间时能购机，成功后不能再次购买。

未使用的采购资金按购机时持份快照记入各持有人的可领取余额。截止后未买成，可调用 finalizeFailure 为每个人记入本金，再各自 withdrawBnb 领取；keeper 当前只提示到期，不代调用 finalizeFailure。分配不逐个向外部钱包转账，一个拒收 BNB 的地址不会卡住其他持有人。

## 如何保持满额后及时采购

筹款期间每 30 秒后台准备候选，每 2 秒读取池状态。原目标直接按池内 NFT 查询官网，API 慢或离线也不妨碍原目标查询。满额后优先使用准备好的队列，逐台做当前挂单查询及一次完整 EVM estimateGas；第一台符合条件即可提交，不等待整批检查完成。链上合约仍重新执行上述约束，模拟成功不保证交易抢先成交。发现候选先按已锁定 taskId 过滤；全部页面的响应累计限制 2 MiB、每页最多 50 行，只接受 JSON 并拒绝重定向。发现请求含响应体共限时 20 秒，RPC 请求设 15 秒 IO 超时；网络故障不允许跳过原有资金约束或清除待确认记录。

程序按实时估算加 20% Gas limit 余量，检查区块上限、账户余额、Gas 单价上限及累计预算。默认累计预算 0.01 BNB，单价上限 1 Gwei，均可配置；它们不是主网实际费用承诺。100 人冷槽本地 mock 测试中，购机调用约 5,831,032 Gas，失败记账约 3,052,347 Gas，不含交易固有 Gas，不替代真实估算。循环最多 100 名持有人，不遍历无限用户列表。

## 待确认交易怎样处理

同一钱包在本机只能有一个执行器。钱包指针保存在 `~/.local/state/pinkuang/purchase-keeper/wallets/`，目录 0700、文件 0600；进程退出仍保留未完成账本指针。此锁不协调其他机器或钱包软件，运行时不能同时拿该钱包手动发送其他交易。

签名后，原始交易及本地计算的哈希先 fsync 持久保存，再调用 RPC 广播。超时、RPC 未索引、进程中断都不会自动分配新 nonce。账本中每个同 nonce 尝试都要查询，因为原交易可能先于加价或取消成交。

结案要求收据身份与原签名一致、区块仍 canonical、至少两次确认，并且交易高度不高于 RPC 报告的 finalized 高度；确认后再次核对区块哈希。节点不支持 finalized 或链尚未最终确认时保留 pending。该做法使用 [BSC 官方提供的 finalized 区块标签](https://docs.bnbchain.org/bnb-smart-chain/developers/json_rpc/bsc-api-list/)，不把 RPC 返回哈希或两次确认当作完成。RPC 必须可信且同步，软件无法保证 BSC 永远不拥堵或不停链。

以下恢复命令需要在 `deploy/` 目录，用原 factory、pool 和 journal 参数执行。KEY 仅由进程环境提供；不要把真实密钥写进命令、日志或仓库。示例中的地址是占位符，不能照抄发送。默认不带 `--send` 只读检查。

```sh
node scripts/purchase-keeper.mjs --factory 0xFACTORY --pool 0xPOOL --journal /private/path/pool.json --once
```

恢复动作必须显式带 `--send --once`，并且下面三个动作只能选一个：

| 参数 | 行为 |
| --- | --- |
| `--rebroadcast` | 发送账本中最新尝试的相同原始字节，哈希不变；如果最新尝试是取消，就是重播取消。 |
| `--speed-up` | 保持同 nonce、同 pool、同 calldata、零 BNB 附带转账，仅重估 Gas 并提高单价。矿机已售或已到期导致模拟失败时停止。 |
| `--cancel-pending` | 同 nonce、零值、空 calldata、自发自收，尝试取消尚未上链的采购。账户有代码或委托代码时停止，需通过钱包核对。 |

提价与取消共用次数上限，默认最多 3 次，可通过 `--max-speed-ups` 设置 0–5 次，硬上限 5。每次单价至少提高 20%，仍受预算与单价上限约束；不同节点的替换规则可能拒收。累计预算保留所有已签尝试中最大的潜在 Gas 费用，降低命令行预算不能撤销历史签名。

取消成功后该 journal 停止采购。取消尝试后若原采购先成功，记录采购成功；若任一尝试上链失败，也停止此取消流程，防止下一轮自动买入。不要为了“继续”删账本：重新采购前必须核实池状态、旧 nonce 已最终结束，并显式建立新的运行记录。

`--pending-seconds` 默认 120 秒，仅标注等待过久，不使交易失效。未知交易占用/消费 nonce、缺失账本、RPC 身份冲突或旧版本终态缺少最终确认证据时停止并要求核实。自动化不会无限加价，也不会在结果不明时改用新 nonce 购买另一台矿机。
