# 预算项目连续采购（2026-09-28）

本轮补齐预算项目运营入口：不用手工另建子池、复制地址再回填。运营者在已募满且仍处于购机期的项目中输入本批金额上限与台数，系统发现候选、展示清单，批准后逐台生成交易。沿用现有 Solidity、永久矿机登记和交易日志，不改变合约费率或角色。

## 实际操作

1. 完整核对官网链上挂单；选择符合剩余预算、单机绝对价格上限与已验证权重单价限制的矿机。官网没有符合本批限额的候选时，才读取并核验 Firsto。
2. 运营者确认本批清单及最高支出，最多 20 台。本批限额是页面中的逐笔确认约束，不是新建链上无限授权。
3. 每台首先确认 `PoolFactory.createPool`，创建固定 NFT、无人认购的子池；创建钱包只付 Gas。子池的募集额向上取整到可整分 100 份的最小 Wei 数，价格上限仍是已批准的精确总价。
4. 确认创建回执后，核对永久登记地址、子池参数、状态和零认购，再确认预算父合约的 `buyOfficial` 或 `buyFirsto`。父项目在同一笔采购交易中持有子池全部 100 份、支付购机款；矿机 NFT 入子池，余款仍归父项目预算。页面不会把子池算作第二个募资项目。
5. 原交易确认后进入下一台。每笔都由钱包明确确认，未启用任何后台签名或无人值守发送。

创建子池与父项目采购是两笔交易，之间存在公开窗口。如果有人先认购了子池，采购会停止，不能声称两步原子完成。已经登记的矿机永久占用项目身份，即使该台失败或被跳过，也不会删除登记后重新建池。

金额展示按 BNB 三位小数四舍五入；精确金额放在提示文本和导出的清单中，审批计算、上限和 calldata 始终使用整数 Wei。官网实际采购款的 1% 项目服务费仍仅从购机结算余款扣除；Firsto 沿用含来源买方费的核验总额，不再加项目采购费。

## 官网完整性与等待时间

真实公开读取发现，官网 JSON 的 `valid` 标记不能代表当前可购买状态。预算发现现在完整枚举固定区块 `1..nextListingId()`，按链上当前挂单价格去重后再筛选，并核对卖家所有权、矿机状态、纯已验证权重和非最优条件。预算发现不依赖官网 JSON 是否遗漏旧挂单。登记过滤也在同一块完成。

聚合器固定使用 Multicall3 地址及 runtime hash，来源和交叉 RPC 验证见 [官网批量读取复核](official-market-batch-review-2026-09-28.md)。最终有界参数为每批 256 个业务读取、最多 8 路并发、单批响应不超过 1 MiB、完整历史不超过 100,000 个 ID、活跃挂单不超过 10,000 项。任何失败、缺项、错误块号或重组均不等于“官网无货”。

2026-09-28 公共节点只读实测，约 21,015–21,016 个 ID 的完整扫描曾耗时 27–44 秒；减少 RPC 数量不保证响应更快。这是运营采购预览，不应阻塞一次 HTTP 请求或在钱包窗口内等待。

新客户端对 `official-candidates` / `budget-candidates` 使用 `async=1`：后台先返回 HTTP 202，前端每 2 秒查询原目标、固定块号和 hash；任务合并，60 秒后台总期限，前端总等待上限 75 秒、单次请求不超过 12 秒。扫描结果必须完整；每次轮询还检查 chainId、区块 hash 与 120 块有效窗口，过期要求重新预览。只有预检通过后才调用已有日志发送器，保留 nonce 和弹出钱包。旧同步查询仍兼容。

单机原目标仍可直接核验官网挂单并购买；普通认购、份额成交和整机买家付款不会调用全市场扫描。完整扫描仅用于运营候选发现或为 Firsto 回退提供官网优先的证据。

## Firsto 与恢复边界

Firsto 当前有数百页矿机数据。页面只读取固定 `viewId` 的前 5 页，明确标注为有界候选，不声称全站最低价；超过 250 项不会阻断候选发现。每个获选签名订单仍须在固定块核对 V2 字节码、签名、卖家、NFT、nonce、来源费用、到期与总支付额，并在每笔发送前重新核验冻结订单。报价源失效或订单不可核验时暂停，不伪造候选。

队列持久记录绑定 chainId=56、钱包、父项目、两 Factory 和 artifact digest，并用读回校验与 revision 比较防止多标签覆盖。队列记录不替代服务器 journal：一旦进入发送器，未知结果只能核对原交易或同 nonce 加速/取消，不能自动重发。

只有根调用者明确证明失败发生在进入发送器之前，例如登录拒绝或重新预览内容变化，才以 `beforeWalletSubmission=true` 将本步骤按 revision 恢复到待建池/待采购。空 journal、超时或缺少交易哈希都不能作为未提交证明。归档回执恢复还核对链上交易的发送人、chainId、nonce、目标、calldata 和金额。

## 验证

新增队列模块 12 项、轮询模块 3 项，原运营 Firsto 16 项回归通过。覆盖官网优先、超过 250 项的 Firsto 有界候选、预算耗尽、矿机重复登记、空子池失效、发送前失败恢复、未知结果不可重发、归档回执 calldata、账户隔离和本地持久冲突。

Linux 私有日志权限、只读扫描 HTTP、原单机 HTTP、脚本全套与旧 live API 的最终结果由本轮发布验收记录补充。本文不表示已发布生产或已进行真实资金采购。
