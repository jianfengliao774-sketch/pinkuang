# 多钱包同时购买：并发核查与测试记录

范围：募集认购、份额市场成交、整机出售成交、官方市场矿机采购，以及相关的页面交易锁、服务器交易记录和链上索引。本轮只在本地 Foundry/Anvil 测试，没有向 BSC 主网发送交易。本记录是针对并发路径的开发审查，不替代独立安全审计。

## 结论和改动

同一区块中的交易仍按确定的先后顺序执行。两个钱包同时争最后的份额或同一个已售罄订单，先执行者成交；后执行者读取更新后的状态并回滚。失败的购买本金不会进入池或市场，但已上链的失败交易仍消耗 Gas。验证过的路径中没有重复铸造、重复出售、重复支付卖家，也没有把失败交易的本金记为负债。验证不能承诺“先点击”者先上链；验证者排序、Gas 出价、重组以及对外部市场的依赖仍会影响最终顺序。

发现并修复一个页面侧阻塞：原先 `deploy/src/market.ts` 用整条 BSC 链共用的浏览器交易锁；同一浏览器的不同钱包互不共享 nonce 和服务器记录，却会互相挡住。现在锁键包含钱包地址：同钱包的多标签页仍串行，不同钱包可以分别签名和提交。市场发送仍在签名前重新核对订单、数量、价格与执行结果。服务器交易意图以钱包隔离，未知回执须最终确认后才能清除；索引器在重组后撤销旧赢家并按规范链重建。

## 已测试的竞争场景

1. **募集认购**：两个钱包按两种顺序争最后 1 份；错误付款、超出剩余份额与 100 份总量限制；一个钱包一次认购 100 份与另一钱包抢先认购；提款和最后一笔认购交换顺序；募集截止前最后一秒及截止秒边界。核对份额总量、成员数、出资、退款债权和 BNB 余额。
2. **份额市场**：两个买家争同一订单的剩余份额，包含先买 60 份后另一人仍尝试买 60 份、再按剩余 40 份成交；不同订单的两笔购买交换顺序；最后 2 份争夺单钱包持满 100 份；卖家撤单与买家成交的先后顺序；订单到期边界；撤单重挂后的旧订单号与旧价格；两次成交间有待分配 BEM 收益。核对锁定份额、卖家及平台 1% BNB 应收、买方持仓、历史收益和失败付款回滚。
3. **整机相关**：两个钱包争同一整机出售；两个钱包重复触发同一池购机；两个已募满的池争同一官方矿机挂单，并对两个弹性购机池争同一替代矿机挂单反转先后顺序。核对 NFT 只交付一次、卖家只收款一次、败方池仍为待购机且募集 BNB 保留、严格收益结清只执行一次。
4. **真实本地链广播**：Anvil 中部署本分支的真实 `ShareMarket` 实现及 ERC1967 代理，用轻量 Factory/Pool 外部接口桩。两个钱包在挖块前各自广播购买同一订单最后 1 份的交易，并被挖入同一区块；恰好一笔成功、一笔回滚。输家余额只减少回执中的 Gas 费用，购买的 1 BNB 没有被扣留；只出现一条成交事件，订单、份额、卖家与平台应收各只变化一次。两个钱包的交易记录在 finalized 后分别结案为成功、回滚。
5. **前端及后端**：同钱包多标签页仍互斥、不同钱包互不阻塞；两个钱包可各自保存同一订单意图和相同 nonce，不互相覆盖服务器修订号；撤单或别人成交后，发送前的最新状态核对阻止陈旧报价。网页只读取到 99/100 份的旧快照时，两个钱包都能生成尚未签名的购买参数；重新读取 100/100 后会拒绝。索引器对乱序日志与重组改换成交钱包保持单笔成交统计和正确持仓。

## 验证命令和边界

`FOUNDRY_PROFILE=ci npm test`：404 项、39 suites 通过，零失败、零跳过；包含本轮新增的 20 项 Solidity 并发用例及两种交易顺序的模糊测试。`npm run fmt:check`、`npm run build` 通过。`deploy` 的 `npm test` 两阶段分别通过 69 项和 103 项（合计 172 项），`npm run build`、`npm run artifacts:check` 通过；`web` 的 `npm run check` 通过 10 项及目录、价格核查，`pnpm build` 通过。PR 的远端检查仍需对本提交重新运行。

Foundry 测试在同一时间戳内顺序调用真实协议合约，验证不同链上排序；Anvil 测试真实地让两笔市场交易先进入待打包队列，再挖进同一块。Anvil 的 Factory/Pool 是接口桩，不能取代 BSC 主网与外部矿机市场集成验证。链上拥堵、验证者排序和外部市场撤单无法用页面预检彻底排除失败 Gas；购买页面应把失败回滚与 Gas 消耗告知用户，并在结果最终确认后刷新链上状态。
