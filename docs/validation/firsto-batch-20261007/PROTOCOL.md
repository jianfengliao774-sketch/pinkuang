## Exact order and fill semantics

Main exchange source path: `verified-sources/src/CircuitBatchAskExchangeV1.sol`.

- `BatchAsk` (lines 39-55): EIP-712 type `BatchAsk(address maker,bytes32 merkleRoot,uint256 batchNonce,uint64 expiry,address payoutRecipient,uint16 feeBps,uint256 feeEpoch,uint16 schemaVersion)`; domain name `Firsto Circuit Batch Ask`, version `1`, chain ID 56, verifying contract exchange address (constructor lines 147-169). `hashBatchAsk` is the EIP-712 digest of `keccak256(abi.encode(typehash, fields))` (175-191). EOA ECDSA and EIP-1271 maker signatures are accepted (450-464).
- `AskLeaf` (lines 42-68): type `AskLeaf(address maker,address collection,uint256 tokenId,uint128 price,address payoutRecipient,uint16 feeBps,uint256 feeEpoch,uint256 batchNonce,uint256 leafIndex,uint16 schemaVersion)`. `hashAskLeaf` is **double keccak**: `keccak256(bytes.concat(keccak256(abi.encode(typehash, fields))))` (193-214). The exchange uses OpenZeppelin `MerkleProof.verifyCalldata` (374-376), which sorts pair values. The official frontend constructs leaves in its selected order, sorts each pair numerically, hashes concatenated `bytes32` pairs, and promotes an unpaired last node; consumers should verify the supplied proof against the signed root rather than reordering leaf identities.
- `fillAsk(BatchAsk,AskLeaf,bytes32[] proof,bytes signature,address nftRecipient)` is payable (226-250). It rejects self-trade, wrong `msg.value`, paused exchange, expired/changed fee or schema, changed shared leaf fields, cancelled/consumed leaf, bad Merkle proof/signature, invalid Factory CPU collection, wrong owner, or missing `isApprovedForAll`. Required BNB is `leaf.price + floor(leaf.price * defaultTakerFeeBps / 10000)` (342-392). It marks the bitmap before the NFT transfer, verifies `ownerOf` after `safeTransferFrom`, pays `leaf.price` to `batch.payoutRecipient`, and accrues the taker fee (226-250).
- `feeEpoch`, `feeBpsAtEpoch`, `defaultTakerFeeBps`, `BATCH_ASK_SCHEMA_VERSION`, `paused`, `factory`, `batchCancelled`, and `isAskLeafInvalidated` are available getters. The latter is true for either whole-batch cancellation or a consumed/manually invalidated bitmap bit (216-224). There is no separate public `filled` getter; use `BatchAskFilled` events to distinguish fills. The bitmap position is `leafIndex >> 8` and bit `1 << uint8(leafIndex)` (445-448).
- A current chain read at block 126089852 found `paused=false`, fee=100 bps, epoch=1, schema=1. A historical public fill receipt `0x73f1e94ac9736937f323aeb9228e3e25af58d60ec4764549ea81aeccffaff2ae` had status 1, and its public batch/leaf hash fixture matches the exchange getters. These values are mutable and must be re-read before any later execution.
