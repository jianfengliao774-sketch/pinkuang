# v2 多矿机页面与服务端队列修复

本次只修改网页、只读报价呈现和部署台 journal，不修改已部署的 Solidity 或合约清单。

- 预算项目创建入口始终向已核验的运营钱包显示。创建时不锁定具体 NFT；募满后可按每批 1–20 台的预算队列逐台采购，同一个父项目共 100 份。
- 采购队列改为钱包会话绑定的 SQLite 服务端记录；跨页面和服务重启按 `account + parent` 恢复，CAS 版本冲突拒绝覆盖，未知交易不能由另一个队列顶替。页面不再将采购队列存入 `localStorage`。
- 创建表单指出具体缺失的金额；展示 Firsto 最新日产能参考价。`521d4c0` 将运营输入改为 `BNB / (BEM / 天)`，从当前 Firsto 已验证、无未验证权重、有效卖单样本中取最低的「日产 BEM / H」比率，向下换算成合约接受的 `BNB / H` 上限。无有效样本、样本超过 120 秒、换算结果为零时拒绝预览；确认页同时列出输入和链上实参。不能把日产能价 9 原样作为合约上限 9 发送。
- 这是建池时的保守折算，不是合约原生的动态日产能价硬约束；Firsto 只提供当时的估计日产出，合约以后不会自动适应全网产能变化。若要在任何未来采买时链上直接按日产能价强制限价，需要新的可信链上产能来源、合约升级及新的部署验收。
- 使用的还是已核验的原有合约产物摘要；页面、API 变更不会自动授权购机或发送钱包交易。
