# 待领取 BEM 展示修复

收益页此前只展示 `PoolVault.claimable(account)`，不包含 `Mining.pending(minerKey)`，尚未归集时会显示零。矿机协议 pending 已产生收益，并不等于矿池已经入账。

修复增加「待归集 BEM（预计）」和预计待领取合计，桌面表格与手机卡片使用同一数据。每池同一 BSC 区块读取工厂登记、池工厂/状态/参数、当前持仓、已入账 BEM、池实际 BEM 余额与已记账负债；对 Active/Listed 池再核对 NFT 所有权、矿机身份和 pending，结束时复核链号及区块哈希。

```text
待归集总额 = Mining.pending + BEM.balanceOf(pool) - pool.bemAccounted
平台费 = floor(待归集总额 / 100)
我的待归集预计净额 = floor((待归集总额 - 平台费) × 当前份额 / 100)
预计待领取合计 = 同块已入账可领取 + 我的待归集预计净额
```

实际归集入账时用户历史小数余数可使新增到账比预计值多一个 BEM 原子（1e-8 BEM）。该数值因此标为预计，不能作为保证到账值。已关闭或未购机矿池不分配协议 pending；零份额用户仍保留历史已入账余额。无法核验时显示「—」，不以零替代失败，部分池失败不显示不完整的总额。

领取按钮只使用同块已入账余额，待归集估计不参与领取授权或交易参数。现有钱包身份、部署身份、用户退出门槛、签名前链上核验、一键归集恢复记录全部保留。读取不签名、不发送交易、不查询报价。

## API 范围

读取仅发生在收益页，限已加载的单矿机项目。币价、Firsto、索引/SSE自动更新不触发新 pending 读取。读取合并重复池，最多三池同时处理，30 秒短缓存并共享在途请求；手动刷新和已确认交易更新绕过旧缓存。两台 Active 矿机一轮共 28 个只读 RPC。没有余额/持仓的空列表不发 RPC，不增加全市场或全钱包扫描。
