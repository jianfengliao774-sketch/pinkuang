# Explicit user-signed cancellation completion

The parent task changed the migration policy on 2026-10-07: conflicting old operations covered by the complete migration are canceled by the user through explicit wallet signatures. This supersedes the earlier proposed unresolved-operation gate; the read-only pending audit remains a historical account of the risk before this decision.

The UI displays “本次将取消已被完整升级覆盖的旧排程，原项目与资金不变” before the start/continue button. It first confirms every canonical 13-component CREATE, then presents each fixed cancellation in order to the selected deployment wallet. Every successful cancellation is matched to the canonical signed transaction and `Cancelled(operationId)` receipt; cancellation records use the same nonce intent, unknown-send, multi-tab and durable persistence protection as the existing transaction flow. Partial cancellation prefixes stay in prepared phase. Schedule and execute require all canonical cancellation receipts, not just timestamp zero. The final completion gate checks the exact cancellation inventory along with the branded full graph proof.

Original operation IDs, calldata, targets, predecessor/salt, ETA and effects remain visible and exported. The agent performs no implicit cancellation, production RPC, wallet signing or mainnet broadcast. Cancel transaction failure is archived and stops that click. Wallet rejection preserves all confirmed deployments and requires a fresh click. Hashless cancel recovery can find only the original nonce-bound transaction; legacy unknown cancel rows cannot use the deployment-only archive escape.

The implementation changes only the new governance24 UI/journal/tests/docs. Shared proof files are owned by the independent proof agent and are symlinked for local validation only; they are excluded from this UI commit. The packaging whitelist remains exactly eight files. Independent release roots remain null until the final root review.

Validation: 79 new TypeScript tests, seven new packaging/preparation tests, and 142 combined old/new TypeScript regression tests passed; TypeScript compilation passed. Cancellation tests cover exact ordering, rejection, lost callback, storage exhaustion, wrong canonical event, nonce-bound import, wrong operation identity/order/nonce, account changes, cross-tab conflicts, failed receipt archives and final-proof completeness. Tests use deterministic local adapters; the canonical full graph/role/timestamp proof is separately tested in the proof change.
