# Stage 2 finalized failure recovery candidate

This is source code for review, not permission to remove `BEMINE_FRESH_STAGE2_HOLD=1` or operate the hardware wallet. The hold defaults to on in `journal-api.mjs` and the attestation unit draft keeps it on. No recovery endpoint sends a transaction.

After the hardware wallet's second through seventh Authority transaction has a finalized failed receipt or a finalized same-nonce replacement/cancellation, the browser first records that outcome as `aborted`. A known winning hash is required; a missing hash, pending receipt or uncertain nonce remains blocked. The browser checks the finalized receipt, the current Factory/Authority/Timelock role prefix, and two nonce views. The journal server independently checks the canonical same-nonce winner, its stored receipt and fee, the finalized role prefix, and an unused next nonce. Its revision-guarded recovery operation moves the entire old step into immutable `attempts[]`, retaining the original and winning hashes, receipt, fee and proof block. Ordinary journal PUT cannot make this transition or erase that history.

Recovery leaves the same action in `waiting` and keeps the old fee in `spentWei`. A new nonce can be requested only by a separate user click; the normal Stage 2 path again pins the action calldata, Gas cap, budget, credential proof, roles and account before calling `eth_sendTransaction`. There is no transaction simulation in this Stage 2 path. The Factory role and code checks read both a finalized anchor and the latest canonical block before the wallet request.

Local tests cover failed step 3, replaced/cancelled step 7, unchanged action with a new nonce, journal history and Gas accounting, unknown winner, unfinalized receipt, reorganization, pending nonce, changed roles, stale tab and the existing 16+7 Anvil success flow. These tests are not a mainnet recovery rehearsal. Before any Stage 2 unfreeze, review this branch, produce a fresh build and package, verify the isolated original-Gas-wallet attestor in its actual unit, confirm the fresh Stage 1 graph and wallet on finalized chain, and rehearse the recovery branch on a disposable fork. Keep the v4 relay and product senders disabled; the v2 sender continues under its own policy.
